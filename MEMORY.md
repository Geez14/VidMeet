# MEMORY.md

> What this agent learned while building VidMeet, written for the next agent picking up the codebase.

## Build context

- **Spec source:** A single prompt asking for a Vercel-deployable 2-person video call app with ≥15 fps, clear audio, a rich-copy invite, an immediate switch to the call screen with a "waiting for joinee" panel, and proper error handling.
- **Stack chosen:** Next.js 14 (pages router) + PeerJS + Tailwind. Reasoning:
  - Next.js pages router gives us a serverless `/api/ip` endpoint trivially, plus dynamic routes for `/call/[roomId]` — and it's the most native target for Vercel.
  - PeerJS abstracts WebRTC signaling using its free public broker. Vercel is serverless and can't host the persistent WebSocket signaling we'd otherwise need.
  - Tailwind keeps the design system small and is friendly to Vercel cold-starts.
- **Render mode:** `/call/[roomId]` is dynamically imported with `ssr: false` because PeerJS / `getUserMedia` need `window`.

## Key decisions & rationale

1. **Room ID = PeerJS ID.** The host registers their PeerJS peer ID equal to the freshly-generated room id (`vm-<10 chars>`). Guests are anonymous peers that dial that id. This is simple and avoids extra signaling indirection.
2. **Room ID alphabet** excludes 0/O/1/I/L to prevent transcription errors when humans read codes aloud.
3. **Copy override.** The InviteCard's primary "Copy" button does **not** copy the URL — it copies a multi-line invite block containing host name, code, direct link, origin city/region/country, IP, timestamp. A secondary "Copy link" button copies only the URL. Both fall back to a hidden-textarea + `document.execCommand('copy')` if the async clipboard API is unavailable (Safari before HTTPS, embedded webviews).
4. **IP & geo gathering.** Two stages: try our own `/api/ip` route first (returns Vercel's geo headers + request IP). If those headers are missing (running locally), augment with a `fetch('https://ipapi.co/json/')`. Both are wrapped in try/catch and fall back to `'Unknown'`.
5. **Constraint cascade for `getUserMedia`.** Start strict (1280×720@30/min15, mono 48 kHz with AGC + EC + NS). On `OverconstrainedError` fall through to 640×360@24/min15, then to `{ video: true, audio: true }`, then to audio-only as a last resort. `NotAllowedError`/`SecurityError` short-circuits this — no point retrying.
6. **Sender tuning.** After the peer connection is up, walk `pc.getSenders()` and set `maxBitrate: 2_500_000` on video and `64_000` on audio; set `degradationPreference: 'balanced'` so we lose resolution rather than frames when bandwidth gets tight (protects the 15-fps floor).
7. **Stats panel.** Polls `pc.getStats()` every 1.5 s. FPS uses `framesPerSecond` if reported, else computes from `framesDecoded` delta. Bitrate from `bytesReceived` delta. RTT from `candidate-pair.currentRoundTripTime` or `remote-inbound-rtp.roundTripTime`.

## Trap I almost fell into

- **Conditional `<video>` mounting race.** The remote `<video>` is conditionally rendered (`{hasRemote ? <video/> : <WaitingPanel/>}`). When `call.on('stream')` fires, `remoteVideoRef.current` is still `null`. The fix is: stash the stream in `remoteStreamRef`, then call `setHasRemote(true)`; a `useEffect([hasRemote])` runs after the DOM mounts and attaches `srcObject`. Mirror logic for the local stream. I added belt-and-suspenders by also attempting an immediate attach inside the `on('stream')` handler in case the element is somehow already mounted.
- **`peer-unavailable` on join.** If the guest hits the room before the host's peer is `open`, PeerJS fires `peer-unavailable`. We catch it in `peer.on('error')` and retry `tryDialHost` once after 1.2 s. Important: the retry guard checks `callRef.current` so we don't re-dial after success.
- **`unavailable-id` on host create (a.k.a. "ID is taken").** The PeerJS public broker keeps stale registrations for up to ~60 s after a tab closes / Fast Refresh remounts. If the user refreshes the host page during dev (or two tabs of the same room race), the second registration is rejected. We catch this on the host side, generate a fresh room id, and `router.replace('/call/<new-id>?host=1')` — silent recovery, no error UI flash.
- **`ipapi.co` CORS/429.** The earlier client-side `fetch('https://ipapi.co/json/')` was both rate-limited and CORS-blocked from the browser. Geo enrichment now happens server-side inside `/api/ip` (uses Vercel headers when present, falls back to a 1.5 s server-side `ipwho.is` lookup). The browser never makes a cross-origin call.
- **ESLint `react/jsx-no-comment-textnodes`.** The editorial design system uses `//` as decorative monospace labels inside JSX text. ESLint flagged every instance. The rule is disabled in `.eslintrc.json` because the strings are intentional — they're not stray code comments.
- **Joining code rejected because it contained dashes.** `formatRoomCodeForDisplay` outputs `XXXXX-XXXXX` for readability. The old `normalizeRoomCode` preserved internal dashes (regex was `[^A-Z0-9-]`), so a user copying the displayed code with dashes failed validation against `^vm-[A-Z0-9]{4,20}$`. Fix: `normalizeRoomCode` now strips ALL non-alphanumerics and re-prefixes with `vm-`. Added a sibling helper `formatJoinInput(raw)` that returns `{ display: 'XXXXX-XXXXX', normalized: 'vm-XXXXXXXXXX' }` for the join input's live formatter.
- **Join input is now forgiving.** The field auto-strips dashes/spaces/case as the user types, shows a fixed `vm-` prefix chip on the left so they only type the body, displays a `n/10` counter and a "Will join: vm-XXXXXXXXXX" preview before submit. Paste a full URL or `vm-XX-XX-XX` or `xxxxxxxxxx` — all collapse to the same canonical id.
- **Secure-context trap on LAN testing.** `navigator.mediaDevices` is `undefined` outside secure contexts. Localhost is exempt; LAN IPs over plain http are not. The dev server hosting machine works fine; every other device on the same Wi-Fi gets a "browser does not support camera/microphone access" error that is actually a context error, not a browser error. Fix in code: `getMediaStream` now checks `window.isSecureContext` and emits a specific message naming http as the cause and pointing at `npm run dev:https`. Fix in tooling: added a `dev:https` script that runs `next dev --experimental-https -H 0.0.0.0` so devices on the LAN can open `https://<laptop-ip>:3000` after accepting the self-signed cert once. README has the full LAN-testing recipe.
- **Camera stayed on after remote-bye.** The guest's local `MediaStream` was never stopped on the `bye` → `setStatus('ended')` path; the call ended but the camera light stayed lit. The host's `handleEnd` stopped its own stream but then immediately `router.push('/')`, leaving the call URL in history — back button revived the room. Fix: refactored to a single idempotent `terminate()` callback that stops both streams, closes the data conn, closes the media conn, destroys the peer, stops stats polling, and writes the room id to `sessionStorage`'s expired list. It's called inline from `handleConfirmEnd` (before `router.replace` unmounts) AND from a `useEffect([status])` watching for `'ended' | 'expired'` (catches the remote-bye path). Both end CTAs now use `router.replace('/')` so the call URL is not in history.
- **Room expiration without a backend.** No server, so expiration is two-pronged: (a) `peer.destroy()` releases the id on the broker, so subsequent guests get `peer-unavailable`; (b) per-tab `sessionStorage` flag (`vm:expired-rooms`) means the same tab can't accidentally re-enter via back button or pasted URL. `VideoCall.jsx` reads the flag in its validation effect and short-circuits to a new `'expired'` status that renders a clean "this meeting has ended" UI with New-Meeting and Home actions. The flag list is capped at 50 ids.
- **Confirmation before end.** Added `components/ConfirmModal.jsx` — themed dialog with backdrop blur, Escape close, focus management, scroll lock, ARIA bits. Host clicking "end" opens the modal explaining "code will expire — can't be reused even by you". Avoids the native `window.confirm` which doesn't match the design system and can't be styled.
- **Single-use chip in InviteCard.** A small signal-tinted note inside the InviteCard ("// SINGLE-USE CODE — expires the moment you end the call") so the host sees the warning continuously, not only inside the confirm modal.
- **SKILLS.md.** Added a comprehensive skills handbook at the project root covering: secure-context / HTTPS, PeerJS id lifecycle and error map, media stream cleanup rules, the state machine, URL/navigation patterns, room expiration model, confirmation UI, design system tokens, a preflight checklist for new components, build gotchas, and what the app deliberately doesn't do. Read it before extending the codebase.
- **Expiration redesign: timestamp-in-id, 24h TTL, no monitoring.** The previous "code expires when host ends" model broke the obvious use case: host generates link, sends it ahead, joins later. By the time they came back, the per-tab sessionStorage flag (or the destroyed peer registration) made the code unusable. The new model encodes the creation timestamp directly into the room id (5 base-31 chars = minutes since 2025-01-01 UTC, then 5 random chars for collision-resistance). Every device that holds the id computes expiry locally — no server, no intervals, no per-code queues. `isRoomExpired` is now a pure decode of the id; if it's past `MEETING_TTL_MS` (24h) it returns true. Single check point: `VideoCall.jsx` validation effect on mount. The previous sessionStorage list is gone. `markRoomExpired` is gone.
- **"End call" now means "leave session."** It doesn't try to kill the code. Closes data conn, destroys peer (releasing the broker id locally), stops media, sends `bye` to the other side, navigates home with `router.replace`. The code is still alive for the rest of its 24-hour window — anyone with the link can rejoin. Modal copy and the InviteCard chip were rewritten to reflect this honestly.
- **Host-comes-back-later: retry the same id, don't mint a new one.** The previous `unavailable-id` recovery generated a fresh id and `router.replace`d to it — which broke the shared link when the original host was just re-opening the URL after a tab close. New behavior in `lib/peerClient.js::createPeerWithRetry`: retry the SAME id up to 4 times with backoff (1.5s, 3s, 4.5s, 6s capped). Total ~15s, easily covers the PeerJS broker's ~60s stale-registration timeout for the common cases. If it still fails after the retries, surface the "this meeting is busy reconnecting / open in another tab" error. The original PeerJS error type is now preserved as `err.peerType` on the rejected Error so callers can branch on specific types without string-matching.
- **Invite text + InviteCard show absolute expiry.** The rich-copy invite payload includes a `Link Expires: <date>  (24h after creation)` line so recipients see when the link dies before they even open it. The InviteCard sidebar replaced the red "single-use" warning with a neutral clock chip showing absolute expiry plus a relative countdown ("23h left").
- **Validation simplified to one path.** Invalid format and timestamp-expired now both resolve to the same `'expired'` status with the "Meeting not found" UI — there's no useful distinction for the user, and the recovery (create or join another) is the same.
- **Reverted the timestamp-in-id design.** It didn't work in practice (George reported "not working", deferred for later). The codebase is back to random 10-char ids. `MEETING_TTL_MS`, `getRoomCreationTime`, `getRoomExpiryTime`, `formatExpiryAbsolute`, `formatExpiryRelative`, `encodeBase31`, `decodeBase31` are all gone. The InviteCard chip is back to "// SINGLE-USE CODE — expires when you end the call". The end-meeting modal copy is back to expressing finality.
- **Broker-as-registry is the new model for "meeting exists".** No 24h TTL, no scheduling. A meeting "exists" iff the host's peer id is currently registered with the PeerJS broker. When the host explicitly ends (or closes their tab and the broker grace period elapses), the registration is dropped — any guest dialing the id gets `peer-unavailable`. The guest's `peer.on('error')` for `peer-unavailable` now retries up to 4 times at 1.5s spacing (~6s total) to absorb the sub-second race between host-clicks-Create and host's `peer.on('open')` firing. After the bounded retries, the guest's status flips to `'expired'` which renders the "Meeting not found" UI. Previously the retry was a single 1.2s attempt, then silence — guest sat on a "connecting" spinner forever for dead meetings.
- **`markRoomExpired` is back, but only as a per-tab back-button guard.** When the host clicks End, the per-tab sessionStorage flag prevents that same tab from sneaking back into the now-dead room via browser history. The broker registration release is the cross-device truth — `markRoomExpired` is only the local back-button shield.
- **React StrictMode disabled in `next.config.js`.** Strict mode double-invokes every useEffect in development to surface idempotency bugs. PeerJS peer registration is fundamentally NOT idempotent — `new Peer(id)` claims the id on the public broker, which holds the registration for ~60s after disconnect (the heartbeat timeout). With strict mode on, every dev page load does: register id X → cleanup destroys peer → re-mount tries to register X again → broker still holds it from the first mount → `unavailable-id` error every time. The "That meeting code is already in use" error George reported on a fresh server restart was exactly this. Production builds don't double-invoke so this only hurt dev iteration, but dev is what we use to build, so strict mode is off. The peerClient error copy for `unavailable-id` was also reworded: it no longer tells the user to "create a new meeting" (misleading when it's their own code being held in broker grace), it explains the broker is releasing the id and to wait a moment.

## What I would do next

- Add a screen-share toggle (`getDisplayMedia` → replace video track via `RTCRtpSender.replaceTrack`).
- Self-host the PeerJS broker on Fly.io or Render to remove the public-server dependency for production.
- Add a TURN server for users behind symmetric NATs (use coturn or Twilio Network Traversal).
- A `/test` page that runs `RTCPeerConnection.getStats` against a loopback to verify bandwidth/CPU before joining.
- Persist a last-used name in `localStorage` so guests don't retype it.
- Light/dark theme toggle (currently dark-only).
- Captions track via the Web Speech API for accessibility.

## Open questions / known limits

- PeerJS public broker is best-effort. Production usage should self-host.
- Mobile Safari can be finicky about `autoplay` + `playsInline`; both attrs are set explicitly.
- `RTCRtpSender.setParameters` is sometimes rejected mid-call; we swallow the error rather than fail the call.
